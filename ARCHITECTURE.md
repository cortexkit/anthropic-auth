# Architecture

## Pattern Overview

**Overall:** Plugin/extension-based Anthropic authentication and routing architecture — a shared core library provides Claude Pro/Max OAuth, account, quota, cache, relay, and routing logic, with separate integration packages adapting it to OpenCode and Pi.

**Key Characteristics:**
- Shared core (`@cortexkit/anthropic-auth-core`) contains all OAuth, quota, cache, relay, and request-signing logic — no duplication between agent integrations
- OpenCode integration operates at the **fetch/request transform** layer: intercepts Anthropic fetch calls, rewrites URLs and request bodies, sanitizes system prompts, and strips tool-prefix on streaming responses
- Pi integration operates at the **provider override** layer: replaces Pi's built-in Anthropic provider with a CortexKit implementation that uses the same shared core
- Sidecar JSON files persist config, fallback accounts, and runtime state — separate from the host agent's own credential store
- Shared core modules own OAuth token exchange, quota/profile API access, Claude Code identity bootstrap, request signing, and relay transport; each platform adapter owns its final direct model-request dispatch

## Data Flow

**OpenCode Request Lifecycle:**

1. **Plugin load** — OpenCode loads `@cortexkit/opencode-anthropic-auth` plugin, which starts background refresh timers, creates `QuotaManager` and `FallbackAccountManager`, creates or loads the main-account slot ID that stays stable when OAuth tokens rotate, initializes RPC server, and registers `auth.loader` + `provider.models` hooks. The model hook publishes Fable 5.1, limited-access Mythos 5.1, Opus 5.5, Sonnet 5.5, and Haiku 5.5 with their native adaptive effort variants, and publishes native adaptive `low` through `max` effort variants for Opus 5 and Opus 5.5 instead of legacy manual-thinking budgets. On boot, the plugin waits for account storage to load before resolving initial sidebar routing from the current shared state. A snapshot taken before the load could otherwise overwrite an active account and route published by another plugin instance during the load. — `packages/opencode/src/index.ts`
2. **Auth loader** — When OpenCode creates an Anthropic session, the plugin's `auth.loader` runs: captures the OAuth `getAuth` function and starts the main token-refresh background loop. Main refreshes are coalesced by account-storage path across every project plugin instance in the process, so a slow host credential write cannot make peer requests time out behind the refresh file lock. Before a main OAuth request uses quota state, the plugin resolves Anthropic's account UUID through Claude Code bootstrap; concurrent lookups for the same access token share one promise, while a request whose credentials genuinely change during resolution aborts. A sticky request whose old access token receives 401 re-reads host auth and directly retries with a concurrently rotated, still-valid access token rather than refreshing the new credential again. The OAuth exchange callback and the post-login acknowledgement read the account store best-effort: a corrupt or partially written file degrades to the missing-entry path and never discards just-exchanged credentials. — `packages/opencode/src/index.ts` (AnthropicAuthPlugin → auth.loader)
3. **Command registration** — Plugin registers `/claude-cache`, `/claude-cachekeep`, `/claude-prime`, `/claude-start`, `/claude-quota`, `/claude-dump`, `/claude-fast`, `/claude-routing`, `/claude-killswitch`, `/claude-account`, `/claude-logging` — `packages/opencode/src/index.ts` (config hook)
4. **Request interception** — OpenCode's messages hook observes messages to mark effort transitions and assign user-turn prompt UUIDs, `chat.headers` injects internal correlation headers (`x-cortexkit-effort-plan`, `x-cortexkit-billing-lineage`), and OpenCode's fetch wrapper intercepts Anthropic fetch calls, resolving and stripping internal headers before dispatch — `packages/opencode/src/index.ts`, `packages/opencode/src/billing-lineage.ts` (experimental fetch wrapping)
5. **URL rewrite** — `rewriteUrl()` adds `?beta=true` to `/v1/messages`, normalizes versioned base paths without duplicating version segments, and overrides base URL when `ANTHROPIC_BASE_URL` or a proxy route `baseURL` is set — `packages/opencode/src/transform.ts`
6. **Request body rewrite** — `rewriteRequestBody()` removes only provably empty trailing assistant messages, refuses meaningful or unknown assistant tails before cache/billing/signing, and strips trailing whitespace after tool_use, normalizes Fable/Mythos 5/5.1, Sonnet 5/5.5, Haiku 5.5, and Opus 5/5.5 adaptive thinking (mapping Sonnet 5.5 opt-outs to `between_tools` and removing its unsupported forced tool choice, enforcing always-on adaptive thinking on Opus 5.5 and normalizing `[1m]` context-window qualifiers via `normalizeAnthropicModelId`), injects the Claude Code 2.1.280 billing header with a bounded process-local suffix pin derived from the initial visible user text and optional request lineage (`cc_prev_req` and `cc_prompt_id`), sanitizes the system prompt (removes OpenCode identity), prepends Claude Code identity, applies cache strategy (explicit/automatic/hybrid), adds fast mode only to Opus 4.8/5/5.5, remaps model names on proxy routes using `ANTHROPIC_DEFAULT_*_MODEL` tier-specific or `ANTHROPIC_MODEL` generic overrides, prefixes tool names and named-tool choices with `mcp_`, removes forced `tool_choice` on Opus 5.5 and Fable/Mythos 5.1 (OpenCode still rejects missing structured output), opts eligible OAuth Fable 5/5.1, Opus 5, and Opus 5.5 requests into Anthropic server-side safety fallback, restores stored fallback boundary markers, conditionally applies the configured Fable 5.1 thinking-prefix behavior only when signed or redacted thinking remains in the outgoing history, keeps top-level Fable 5.1 effort anchored to the earliest retained turn while inserting later effort changes as empty system markers, applies cache diagnostics opt-in (`diagnostics.previous_message_id`), shapes a correlated OAuth lane-start request to one output token without thinking, strips request lineage before reusing bodies in source cache warming or prewarming, and creates `cch` over the final serialized body — `packages/opencode/src/transform.ts`, `packages/opencode/src/server-fallback.ts`, `packages/core/src/thinking-binding.ts`, `packages/core/src/model-remap.ts`, `packages/opencode/src/cache-diagnostics.ts`, `packages/core/src/cch.ts`
7. **Routing** — `shouldFallbackStatus()` checks if response should trigger fallback; `FallbackAccountManager` iterates accounts in ordered modes, while `StickySessionRouter` assigns cold sessions by reset-normalized spendable OAuth quota and weighted initial-prompt deficit, then persists hashed session affinity across processes/restarts. Sticky routes retain transient failures, including DNS-related refresh backoffs on a fixed five-minute retry interval while the fallback's current access token remains valid, hold confirmed 5h exhaustion when reset is within 15 minutes, and migrate for longer confirmed exhaustion/permanent account failure. All modes respect model-scoped quotas and killswitch thresholds (including per-model scoped thresholds). API-key routes remain excluded until fresh general OAuth exhaustion is confirmed; model-scoped exhaustion can move only among OAuth accounts. A complete sticky pool with no eligible route returns an explicit 401 for a permanent main-account authentication failure, an explicit 401 naming fallback OAuth accounts that require re-login, or a quota-policy 429 rather than falling through to an excluded account; incomplete pools fail retryably. Killswitch blocks are classified as scoped-driven (matching a specific model's weekly limit) or account-level (5h/7d limits) with a model-specific or generic retry hint — `packages/core/src/routing.ts`, `packages/core/src/sticky-routing.ts`, `packages/core/src/accounts.ts`, `packages/opencode/src/index.ts`
8. **Relay** — `sendViaRelay()` sends full or patched body to Cloudflare Worker, which streams Anthropic response back. HTTP relay responses and WebSocket `response_start` control messages deliver genuine upstream headers to the OpenCode account-bound quota harvester and billing lineage tracker (committing upstream `req_*` request IDs for subsequent session turns); synthetic optimistic response headers are never harvest input, and relay-to-direct fallback stays owned by the direct path — `packages/core/src/relay.ts`, `packages/opencode/src/index.ts`
9. **SSE stream and content-filter safety fallback** — By default, OAuth Fable 5/5.1 and Opus 5 requests send `fallbacks: "default"` with Anthropic's `server-side-fallback-2026-07-01` beta. The stream wrapper detects initial `fallback` blocks, sticky `fallback_message` usage iterations, and restoration to the requested model. Because OpenCode does not natively preserve `fallback` content blocks, the wrapper rewrites each block into a hidden signed thinking marker for storage, then the next eligible request restores the exact Anthropic fallback boundary before signing and sending. If an eligible OAuth response still terminates in refusal, the deterministic 10-successful-response Opus 4.8 recovery activates as a client-side backstop. Source-model prewarms explicitly remove `fallbacks` so they cannot be sticky-routed back to a fallback model. If a served fallback completes a `tool_use` before its terminal refusal, the wrapper preserves that completed call, changes the terminal finish to `tool_use`, and lets OpenCode continue on Opus 4.8 with the existing `tool_result` instead of replaying the tool. The active Anthropic-selected target and later restoration are written per session to the TUI sidebar state; when no matching TUI is connected, OpenCode Desktop receives an ignored/no-reply `promptAsync` notice that the plugin schedules delivery as soon as `session.idle` is observed instead of waiting for a later `session.updated` event, which OpenCode 1.18 no longer emits after idle; delivery still escapes the awaited event handler with `setImmediate` because OpenCode evaluates the run-loop exit condition only after awaiting event handlers. Intermediate `tool-calls` completions do not flush notices. When a refusal arms client recovery, the Desktop switch notice is not queued until the first downgraded Opus response completes successfully, so a transient idle state between the refused source response and OpenCode's internal retry cannot insert a user message or consume the retry response. The plugin probes `session.status()` outside that critical section and revalidates its idle-delivery lease after both the asynchronous status lookup and prompt-context lookup so a new prompt cannot adopt the ignored notice as its retry parent. A newly created user-message event revokes that lease before OpenCode's later busy-status event, while repeated updates for the user message that produced the current idle event do not suppress delivery; if multiple fallback state changes overtake delivery, only the newest notice is retained. Delivered notice message IDs are tracked per session (bounded to four IDs across at most 128 recently used sessions) and excluded from user-message lease revocation so the plugin's own notice cannot cancel its successor; delivery additionally requires the notice still head its queue, with a superseded queue looping to the newest instead of dropping it. Inconclusive probes re-arm for at most four attempts, with attempt 0 on `setImmediate` and later attempts delayed by `25` ms multiplied by the attempt number, and requires message-ID placement before the active assistant; consecutive notices use strictly increasing IDs bounded by that assistant, taking both host history and the latest locally prepared notice into account. If no safe ID can be allocated, delivery stays queued rather than letting the host mint an untracked ID. IDs are registered before dispatch so the notice's own user-message event cannot revoke its delivery lease. This removes the unsafe host-assigned-ID fallback when placement fails. Custom API-key routes strip the beta and `fallbacks` field. Setting `OPENCODE_ANTHROPIC_AUTH_FALLBACK_MODE=legacy` bypasses the server policy and uses the same deterministic Opus 4.8 recovery from the first refusal, keyed by session and source-model family with account-bound source-model prewarming and standby cache bridges beyond Anthropic's 20-block lookback — `packages/opencode/src/transform.ts`, `packages/opencode/src/server-fallback.ts`, `packages/opencode/src/fable-fallback.ts`, `packages/opencode/src/prompt-context.ts`, `packages/opencode/src/index.ts`
10. **Sidebar update** — `writeSidebarState()` writes quota/routing/cache state plus bounded per-session server-side fallback and deterministic recovery status to a JSON file read by the TUI sidebar widget (separate process via RPC). Routing-authoritative writes (e.g. active routing decisions) are distinguished from display-only/metadata writes (e.g. quota refreshes or command paths). Display-only writes re-read the file and merge state to preserve any live routing session's `activeId` and route. Cross-process writes are synchronized using an atomic `mkdir` directory lock with jittered retries, rename-claim eviction (tolerating `ENOENT` and `EINVAL` race conditions during marker eviction), and lock-budget exhaustion skips. The write is fenced: ownership is verified before and after the rename, triggering one bounded locked repair of routing-authoritative fields on post-rename loss. — `packages/opencode/src/sidebar-state.ts`, `packages/opencode/src/index.ts`

**Pi Request Lifecycle:**

1. **Extension load** — Pi loads `@cortexkit/pi-anthropic-auth` package, which calls `registerCommands()` and `pi.registerProvider("anthropic", ...)`, and hooks `turn_start` to derive Fable 5.1 effort history directly from the session branch (deriving compaction trims locally when `buildContextEntries()` is absent) — `packages/pi/src/index.ts`, `packages/pi/src/effort-history.ts`
2. **Provider registration** — Provider defines OAuth login/refresh functions (delegating to core's `authorize`/`exchange`/`refreshClaudeOAuthToken`), exposes the CortexKit model catalog including Fable 5.1, limited-access Mythos 5.1, Opus 5/5.5, Sonnet 5.5, and Haiku 5.5 (with native request-wide pricing tiers above 100K input), and registers a `streamSimple` function — `packages/pi/src/index.ts`
3. **Request conversion** — `buildAnthropicRequest()` builds the Claude Code-compatible body and signature. Pi's transcript-replay helpers live in `packages/pi/src/transcript.ts` rather than being imported from the host SDK at runtime, because Oh My Pi's legacy Pi SDK shim does not export them; the emitted Pi bundle's host imports are syntax-checked in CI and release. Flattens host system prompts whether provided as strings or ordered prompt blocks (e.g. Oh My Pi string/text block arrays) on blank lines so the paragraph split classifies identical text. The recognized Pi documentation paragraph is kept out of top-level `system[]`—where its path-enumeration/cross-reference text can cause OAuth billing rejection—and is prepended as a separately cached block before the first user's text. If Pi changes the documentation heading or prompt layout, the converter moves the complete host prompt to that safe cached block rather than restoring the rejected top-level shape. Signed thinking is replayed only when the stored assistant message came from the same Anthropic API and model as the current request, matching Pi's built-in origin check; foreign signatures are stripped before Anthropic validation while visible reasoning is retained as ordinary text. Pi redacted reasoning maps losslessly to Anthropic `redacted_thinking`. The converter pins the first-user billing suffix per Pi session, places cache breakpoints without exceeding 4 blocks by walking cache control holders and keeping automatic and hybrid placement separate, and an OAuth Fable 5.1 continuation with replayed signed or redacted thinking adds `thinking.block_binding.prefix_mismatch_behavior = "drop_block"` plus the matching beta so compaction drops stale thinking instead of rejecting the request; first turns and API-key routes receive neither control. — `packages/pi/src/convert.ts`, `packages/core/src/thinking-binding.ts`
4. **Stream implementation** — `streamCortexKitAnthropic()` in `packages/pi/src/stream.ts` sends via relay or direct, handles ordered or persistent sticky-balanced routing (including model-scoped OAuth routing and the confirmed-general-exhaustion gate for API-key routes), configures version-normalized base paths (`buildExplicitBaseMessagesUrl`) and safe proxy custom headers (`applyCustomHeaders`) for API-key routes, manages cache keepalive, maps returned Claude Code tool names against the same normalized host tool set used to build the outgoing request (Pi ≥0.86 puts tools in transcript system messages rather than `context.tools`), and converts streamed `redacted_thinking` blocks into Pi's replayable redacted reasoning representation
5. **Slash commands** — `/claude-*` commands registered in `packages/pi/src/commands.ts` reuse core command execution functions

**Quota Refresh & Header Harvest Flow:**
1. Background timer fires at `checkIntervalMinutes` (default 5) — `packages/core/src/quota-manager.ts`
2. `QuotaManager.refreshMain()` fetches `https://api.anthropic.com/api/oauth/usage` (including standard five-hour/seven-day windows and weekly scoped model limits) with the access token, but keys the result and its backoff to the stable account identity rather than the rotating token
3. On success: persists the account-identity-bound quota snapshot (including a top-level `checkedAt` freshness timestamp to support merge resolution of windowless empty-scoped quotas) to the sidecar state file and updates sidebar state. Scoped custody keys main by the discovered primary account UUID rather than the local host slot; an authorized receipt is rejected if the roster primary changes before identity binding. When main has only header-sourced 5h/7d values, it stays due for a first usage poll to learn model-scoped limits. Failed physical polls are spaced per account; lock-losing contenders do not consume that interval — `packages/opencode/src/index.ts`, `packages/core/src/quota-manager.ts`
4. On 429: records backoff with `nextRetryAt` timestamp — prevents further refreshes during backoff — `packages/core/src/accounts.ts`
5. Quota-endpoint 403 policy/auth failures bypass quota and refresh backoff rather than being misclassified as rate limits — `packages/core/src/accounts.ts`, `packages/core/src/quota-manager.ts`
6. Fallback accounts: `FallbackAccountManager` refreshes per-account quotas in background, persists to state, and notifies the sidebar. Persisted fallback quota cache seeds use the freshest timestamp across top-level, standard, and model-scoped windows, preventing an unnecessary usage fetch when only fresh scoped quota data is available. Concurrent refresh-lock waiters preserve the original classified refresh failure rather than replacing a permanent `invalid_grant` with an unclassified wrapper error — `packages/core/src/accounts.ts`, `packages/core/src/quota-manager.ts`, `packages/opencode/src/index.ts`
7. Passive header harvesting: Upstream response headers (`anthropic-ratelimit-unified-*`) on direct fetch and HTTP/WebSocket relay transports are passively harvested (`normalizeQuotaHeaders`). Main-account observations are fenced by the request's resolved account UUID and fallback observations by auth lineage before persistence; header-owned 5h/7d values merge without dropping poll-owned scoped windows, binding metadata, or extra usage. Sidebar display writes are queued after storage/cache reconciliation rather than delaying the provider response — `packages/core/src/quota-headers.ts`, `packages/opencode/src/index.ts`
8. Optional host-local feed: when `quotaHeaderFeed.enabled` is true at plugin startup, successfully persisted header observations are projected into an explicit quota-only allowlist with per-field provenance and written to an owner-only per-process lease file. Consumers deduplicate entries by stable account reference and ignore observations at or beyond the three-minute lease; tokens, raw headers, request bodies, model IDs, and refresh errors are never published — `packages/core/src/quota-header-feed.ts`, `packages/opencode/src/index.ts`
9. Account profile metadata: Organization tier metadata (`Max 5x`, `Team · Max 5x`) is fetched from `https://api.anthropic.com/api/oauth/profile` (`fetchOAuthAccountProfile`), bound to the stable account identity, cached with a 7-day TTL, and persisted fire-and-forget without blocking user command execution. Legacy token-fingerprint profile state remains loadable for migration — `packages/core/src/oauth-profile.ts`, `packages/core/src/accounts.ts`

**Optional Claustrum Global-Custody Flow:**
1. OpenCode and Pi support optional global Claustrum vault custody for all Anthropic OAuth accounts. Under zero-bind scoped custody, each host enrolls independently (`anthropic-auth-opencode` and `anthropic-auth-pi`), receives a `category:anthropic-native` read grant, and discovers all active Claude accounts automatically via `credential.list_scoped`. In `local` mode the plugin performs no vault calls. Old handle-based OpenCode configurations without a scoped roster fail closed; `opencode-anthropic-auth setup` enrolls and activates both hosts without capability handles — `packages/core/src/accounts.ts`, `packages/core/src/claustrum-scoped-runtime.ts`, `packages/opencode/src/custody-mode.ts`, `packages/pi/src/custody.ts`, `packages/opencode/src/setup/`
2. Main's OpenCode auth slot retains only an OAuth-shaped, non-secret tombstone so `auth.loader` and the custom fetch remain active. The setup wizard (`setup`) installs the tombstone and checks the host process fence immediately before writing. Pi uses native ambient auth without an auth tombstone; setup prompts for explicit consent to remove any conflicting stored local Anthropic OAuth token so Claustrum custody can serve requests — `packages/core/src/claustrum.ts`, `packages/opencode/src/setup/activation.ts`, `packages/pi/src/index.ts`
3. Zero-bind discovery and roster projection: `refreshClaustrumScopedRoster` atomically discovers vault accounts under lock, projects secret-free tombstone routing rows into `anthropic-auth.json`, maps the unlabelled default (`oauth:anthropic`) to primary, preserves API-key routes and user preferences, and removes local credentials. When `ck auth login --provider anthropic` adds a new account to the vault, `ClaustrumScopedRuntime`'s periodic discovery poll detects it, updates routing state, and primes its quota for sticky-balanced routing with zero downtime and no restart — `packages/core/src/claustrum-scoped-roster.ts`, `packages/core/src/claustrum-scoped-runtime.ts`
4. Per-dispatch scoped authorization: Quota polling, profile hydration, CacheKeep prewarms, Prime ticks, and model requests freshly authorize via `getScoped` with a five-minute serving margin (`CUSTODY_PREFLIGHT_MIN_TTL_MS = 300_000ms`). Bearer material is never cached in consumer memory or sidecar state. A genuine 401 on replayable model requests, CacheKeep prewarms, Prime fires, or quota/profile GETs triggers one bounded replay only when fresh authorization returns a different record version for the same credential and account; otherwise the exact rejected version is reported through `reportAuthFailureScoped`. OpenCode and Pi both authorize relay-to-direct fallbacks separately so they never reuse an earlier relay receipt. OpenCode maps the stable main-quota UUID to the `main` scoped route before quota dispatch. A relay's own 401 without an Anthropic request ID uses direct fallback where allowed or returns 502, never a false permanent OAuth 401 — `packages/core/src/claustrum-scoped.ts`, `packages/core/src/claustrum-scoped-runtime.ts`, `packages/pi/src/stream.ts`, `packages/opencode/src/index.ts`
5. Consumer enrollment ceremony: OpenCode and Pi use separate `anthropic-auth-opencode` and `anthropic-auth-pi` identities. Only the explicitly invoked, offline setup wizard proposes and polls enrollment: it persists a 32-byte request secret under an owner-only file lock before proposing, resumes it after a crash, approves via `ck auth enroll approve`, grants `category:anthropic-native` read access, and commits the one-shot token before replacing pending metadata. A daemon-confirmed dead request may be reset and reproposed at most once during that setup action. The consumer classifies Claustrum's closed permanent refusal codes by code despite older client transport labeling them retryable; a blocked state stops any older poller that subsequently reads the shared state. Previously running plugin processes still need to be stopped or restarted to adopt the explicit-only behavior. OpenCode boot and `/claude-account` only read the enrollment state; `/claude-account enrollment-reset` clears terminal state under lock without proposing, and instructs the user to rerun setup. No plugin process owns a recurring enrollment poller — `packages/core/src/claustrum-enrollment.ts`, `packages/opencode/src/setup/claustrum.ts`, `packages/opencode/src/index.ts`
6. Interactive setup wizard: `bunx @cortexkit/opencode-anthropic-auth setup` provides one-step detection and configuration for OpenCode and Pi. It detects installed hosts, verifies running processes, updates `opencode.jsonc` and `tui.jsonc` (comment-preserving), installs the Pi extension via `pi install`, activates Claustrum custody, and verifies end-to-end credential reach — `packages/opencode/src/setup/command.ts`, `packages/opencode/src/cli.ts`
7. Direct, relay, CacheKeep, Prime, and quota/profile paths retain per-attempt scoped record-version provenance for 401 reporting. Replayable requests retry at most once when a genuine 401 is followed by an advanced scoped record for the same account; authorization failures never fall back to local OAuth credentials — `packages/core/src/claustrum-scoped.ts`, `packages/opencode/src/index.ts`, `packages/pi/src/stream.ts`
8. A late scoped connector is closed if shutdown wins the race, and waiting dispatches are rejected rather than resurrecting the runtime — `packages/core/src/claustrum-scoped-runtime.ts`

**Cache Keepalive Flow:**
1. `CacheKeepManager` tracks recently used hybrid-cache sessions and their associated `oauthAccountId` — `packages/core/src/cachekeep.ts`
2. ~5 minutes before the 1-hour cache TTL expires, sends a `max_tokens: 0` pre-warm request (authenticated using the corresponding main or fallback account credentials) to extend the cache entry. A failed prewarm keeps the last known cache expiry, schedules a bounded retry while that cache can still be alive, and removes the target only when the confirmed cache lifetime ends.
3. Timer and manual ticks share one in-flight promise, preventing overlapping prewarms or duplicate lease-registry publications for the same target.
4. Removes streaming plus incompatible manual-thinking, structured-output-format, and forced-tool-choice fields from the pre-warm body, and strips request-scoped billing lineage (`stripBillingLineageFromBody`).
5. Each manager publishes session IDs and cache timing (never request bodies, headers, or tokens) to a host-scoped temporary lease registry; status commands aggregate live records across project/plugin processes, and stale process records age out after three minutes. Schedule mode can be a local hour window or `always`, which remains active across midnight while the process is open

**Quota Priming Flow:**
1. `/claude-prime` parses status, `on`, and `off` actions; toggles persist only the `prime.enabled` flag in account configuration, while status projection combines the main account and enabled OAuth fallbacks with due times, transient attempt results, persisted usage counters, and estimated cost — `packages/core/src/prime.ts`, `packages/core/src/accounts.ts`, `packages/opencode/src/index.ts`
2. The OpenCode plugin adopts one `PrimeManager` per account-storage identity through a process-wide registry; instances sharing a storage path rebind the existing manager on reload, while a storage-path change stops and removes the old manager when its last project slot leaves — `packages/opencode/src/prime-manager-registry.ts`, `packages/opencode/src/index.ts`
3. An enabled manager runs an unref'd 60-second interval; every tick sweeps stale markers, reloads persisted state, and evaluates the main account plus configured accounts. An account is due when its persisted five-hour `resetsAt` plus the 60-second due offset has passed; an unknown reset uses the bootstrap claim path — `packages/core/src/prime.ts`
4. A due OAuth account performs one fresh quota check through `refreshMainWithMetadata()` or the fallback refresh path before claiming. Cached or stale results never claim, a future fresh reset marks the window active instead of priming, and the Haiku request is rejected by the account or model-scoped killswitch policy before claim — `packages/core/src/prime.ts`, `packages/core/src/quota-manager.ts`, `packages/opencode/src/index.ts`, `packages/core/src/accounts.ts`
5. The manager derives a storage-path namespace and account-auth-lineage fingerprint, then atomically creates an account-and-reset marker with `writeFile(..., { flag: 'wx' })`; the storage namespace isolates independent config stores, the account namespace prevents credential-lineage reuse, and the first process to create the marker is the only process that fires for that reset epoch — `packages/core/src/prime.ts`, `packages/core/src/accounts.ts`, `packages/opencode/src/index.ts`
6. The winner sends one authenticated `POST` request through the normal request rewrite path with model `claude-haiku-4-5`, `max_tokens: 1`, system instruction `Reply with 1 when you receive 0.`, and user message `0`; the request has a 30-second timeout and records response usage when available — `packages/core/src/prime.ts`, `packages/core/src/models.ts`, `packages/opencode/src/index.ts`
7. A successful fire atomically increments the account's cumulative input/output token counters and count in runtime state, updates manager/sidebar status, and schedules a 90-second unref'd quota refresh so the newly started window is persisted after usage propagation; stopping or disabling the feature aborts in-flight work before claim or send — `packages/core/src/accounts.ts`, `packages/core/src/prime.ts`, `packages/opencode/src/index.ts`, `packages/opencode/src/sidebar-state.ts`
8. Marker cleanup recursively removes files older than six hours from the storage namespace, allowing abandoned claims to age out without allowing concurrent processes to reclaim a live marker — `packages/core/src/prime.ts`

**Explicit Lane Start Flow:**
1. `/claude-start` resolves the current session's agent, model, and variant from message history, then queues the exact visible synthetic marker `[lane start] — automated cache warm; no response needed.` through OpenCode's `session.promptAsync()` path — `packages/opencode/src/lane-start.ts`, `packages/opencode/src/prompt-context.ts`, `packages/opencode/src/index.ts`
2. `LaneStartTracker` correlates the synthetic message ID with `chat.message` and `chat.headers`, adding a one-shot internal header only to the matching request. Pending IDs are session-scoped and bounded, so an interleaved real user turn or another session cannot inherit the shape — `packages/opencode/src/lane-start.ts`
3. The fetch wrapper consumes and strips the internal header before dispatch. OAuth routes continue through normal model normalization, cache strategy, quota/killswitch routing, relay/direct transport, signing, diagnostics, and CacheKeep discovery, but set `max_tokens: 1` and remove thinking. API-key routes remain ordinary, including their response bytes — `packages/opencode/src/index.ts`, `packages/opencode/src/transform.ts`
4. For an OAuth-served lane start, the SSE wrapper rewrites only the terminal `max_tokens` stop reason to `end_turn`; refusals and other finish reasons remain unchanged. Dump artifacts use the `start` tag and cache diagnostics use `source: "start"` — `packages/opencode/src/transform.ts`, `packages/core/src/dump.ts`
5. The command is explicit and one-shot; it has no automatic or persisted mode. Subsequent CacheKeep activity comes from the normal request-discovery path after the lane-start request succeeds.

**QuotaHeaderFeedRegistry:**

- Location: `packages/core/src/quota-header-feed.ts`

The feed contains quota windows, per-field provenance, resolved Anthropic account UUIDs, and opaque identity metadata only, never credentials or raw transport data.

**FallbackAccountManager:**
- Purpose: Manages background token refresh and quota fetch for fallback OAuth/API accounts
- Location: `packages/core/src/accounts.ts`
- Pattern: Created per-plugin-instance; iterates accounts and schedules per-account refresh timers

**ClaustrumScopedRuntime:**
- Purpose: Discover native Claude OAuth accounts and authorize each outbound operation independently for OpenCode and Pi
- Location: `packages/core/src/claustrum-scoped-runtime.ts`, `packages/core/src/claustrum-scoped-roster.ts`, `packages/core/src/claustrum-scoped.ts`
- Pattern: Each host has a separate owner-only enrollment token and an `anthropic-native` read grant. A process-shared connection and locked roster reconcile non-secret account metadata; individual sends acquire a fresh scoped receipt with a five-minute validity margin. Per-attempt 401 reports use the version that supplied the actual request; revoked or unavailable credentials cannot fall back to sidecar material. An incomplete roster or mismatched OpenCode tombstone refuses serving.

**StickySessionRouter:**
- Purpose: Quota-balance cold sessions without moving an established prompt cache between OAuth accounts
- Location: `packages/core/src/sticky-routing.ts`
- Pattern: Cross-process locked atomic registry keyed by SHA-256 session hashes. Candidate weights combine spendable 5h/7d/model-scoped quota, reset horizon, and bytes assigned since the candidate quota snapshot. Assignments survive transient errors, can be cleared for the current session with `/claude-routing reset`, and expire after seven inactive days. Affinity is bound to the user-selected model: changing models discards the old assignment and its stale CacheKeep preference before quota-based reselection, while an internal Fable/Opus recovery model continues on the original account. Legacy assignments without a model identity are reallocated once rather than guessed. Direct Opus allocation first consumes usable accounts with exhausted Fable scope.

**CacheKeepManager:**
- Purpose: Tracks hybrid-cache sessions and sends pre-warm requests before 1-hour TTL expiry; also exposes immediate zero-output prewarming for Fable/Opus 5 content-filter recovery
- Location: `packages/core/src/cachekeep.ts`
- Pattern: In-memory target tracking with configurable local window or process-lifetime `always` schedule; tracks the associated `oauthAccountId` to pre-warm using the correct credentials; supports up to 32 concurrent sessions per manager and publishes sanitized tracking snapshots on changes/heartbeats

**CacheKeepSessionRegistry:**
- Purpose: Aggregates current CacheKeep session visibility across independently loaded OpenCode project plugins or Pi processes without sharing request payloads or credentials
- Location: `packages/core/src/cachekeep-registry.ts`
- Pattern: One atomic JSON lease record per manager under the system temporary directory; records contain only session IDs and cache timing, are separated into OpenCode/Pi scopes, deduplicate by session ID, and are ignored after a three-minute stale lease

**CacheDiagnosticsTracker:**
- Purpose: Binds previous Anthropic response message IDs for `cache-diagnosis-2026-04-07` opt-in and constructs schema v:2 `MC-CACHE-DIAG ` records with TTL token breakdown, diagnostic state, and attribution
- Location: `packages/opencode/src/cache-diagnostics.ts`
- Pattern: Bounded in-memory map of prior response IDs (`CACHE_DIAGNOSTICS_SESSION_LIMIT = 1000`) and deduplicated beta header hashes (`CacheDiagnosticsBetaTracker`), emitting debug-level log records, beta side-channel lines, and short-gap canary warnings

**PrimeManager:**
- Purpose: Schedules opt-in five-hour quota priming for each OAuth account and projects per-account status
- Location: `packages/core/src/prime.ts`
- Pattern: Unref'd 60-second interval with fresh quota and killswitch gates, cross-process atomic marker claims, minimal Haiku requests, runtime usage persistence, delayed quota refresh, and idempotent start/stop lifecycle

**PrimeManagerRegistry:**
- Purpose: Shares one PrimeManager across OpenCode plugin instances that use the same account storage path
- Location: `packages/opencode/src/prime-manager-registry.ts`
- Pattern: Process-wide map keyed by a SHA-256 storage-path fingerprint; project slots hold generation-fenced adoption leases, so a late predecessor disposal cannot release a same-slot successor. Reloads rebind current closures, and the last valid lease release stops and removes the manager.

**ServerSideFallbackStreamRewriter:**
- Purpose: Opts eligible OAuth Fable 5/5.1 and Opus 5 requests into Anthropic's default safety fallback, preserves fallback conversation boundaries across OpenCode storage, and classifies active/restored fallback outcomes
- Location: `packages/opencode/src/server-fallback.ts`
- Pattern: Request-time restoration converts CortexKit-signed hidden markers back to Anthropic `fallback` blocks before `cch` signing. The streaming rewriter converts newly returned fallback blocks into hidden thinking markers that OpenCode can persist, observes top-level served models and `usage.iterations[].type === "fallback_message"`, and emits one outcome at the terminal message delta. It also tracks completed `tool_use` blocks: when a terminal refusal follows one, it activates client recovery and exposes a normal `tool_use` finish so OpenCode preserves the call and continues with the existing result. Marker restoration is enabled only for eligible server-fallback requests; custom API-key routes drop internal markers and server-fallback opt-ins.

**ThinkingBindingControls:**
- Purpose: Controls how Fable 5.1, Opus 5.5, Sonnet 5.5, and Haiku 5.5 handle replayed thinking whose original conversation prefix changed after host compaction or prompt transformation
- Location: `packages/core/src/thinking-binding.ts`
- Pattern: Shared outgoing-body inspection recognizes non-empty signed `thinking` and `redacted_thinking` blocks. OAuth Fable 5.1, Opus 5.5, Sonnet 5.5, and Haiku 5.5 continuations with adaptive thinking use `thinkingBinding.prefixMismatchBehavior`: `account-default` omits the local override and lets Anthropic handle changed-prefix thinking for the OAuth account serving the request; the plugin does not implement or infer that server policy, while `error` or `drop_block` adds `thinking.block_binding.prefix_mismatch_behavior` and beta `thinking-binding-controls-2026-08-01`. Sonnet 5.5's `between_tools` mode rejects this field and does not receive it. First turns, Mythos 5.1, older models, and API-key routes remain unchanged.

**MidConversationOutputConfig:**
- Purpose: Preserves Fable 5.1 prompt-cache prefixes while users change reasoning effort between turns
- Location: `packages/core/src/mid-conversation-output-config.ts`, with host history adapters in `packages/opencode/src/effort-history.ts` and `packages/pi/src/effort-history.ts`
- Pattern: The top-level `output_config.effort` remains anchored to the earliest retained effort. Later changes become empty `role: "system"` messages immediately before their user/tool-result boundary. OAuth Fable 5.1 requests always include `mid-conversation-output-config-2026-07-01`; other models and API-key routes do not. Before OpenCode lowers host records into Anthropic messages, it adds stable, checksum-bound transition markers to lowerable user boundaries and, when transitions exist, a plan-bound anchor at the current user boundary. The messages hook records the expected timeline in a bounded request tracker; the later `chat.headers` hook attaches a fixed-size plan through an internal header after every message transform has run and retains it for automatic retries of the same message. The fetch transform validates the lowered markers against that trusted timeline. A current-boundary anchor may precede a trailing user-role `tool_result` only when every such block matches a `tool_use` in the immediately preceding assistant. Consecutive host user records can merge into one wire user message: the flat marker sequence must still match the plan, and the last transition on that boundary supplies the effective effort. If a downstream transform legitimately trims a history prefix, the surviving markers must be an exact suffix and the current-boundary anchor must match the original plan; consumed transitions are folded into the retained top-level baseline. A bounded, message-revocable history retains an older request plan if the same user message is re-planned after compaction while its header is still in flight. Total marker loss without a surviving authenticated anchor remains fail-closed: the remaining body cannot establish that only a prefix was removed. Holes, reorderings, mutations, or a missing/mismatched anchor still fail locally before cache shaping, billing-suffix derivation, dumping, signing, or transport. A missing-all refusal logs only its marker count, resolved-plan status, last retained user index/block counts and expected anchor hash; no prompt content or marker bytes are emitted. The transform strips all markers and the internal header before dispatch. Stable marker identity prevents a downstream transform's persisted source text from resurrecting an obsolete per-pass nonce. This avoids both assistant-record count assumptions and transform-order coupling in tool-heavy or compacted histories. Pi rebuilds transitions directly from active compaction-aware session entries on each turn.

**FableFallbackManager:**
- Purpose: Provides deterministic 10-successful-response Opus 4.8 recovery as the default server policy's refusal backstop and as the exclusive policy under `OPENCODE_ANTHROPIC_AUTH_FALLBACK_MODE=legacy`
- Location: `packages/opencode/src/fable-fallback.ts`
- Pattern: Bounded, expiring in-memory map keyed by session and source-model family (recognizing context-window-qualified models like `[1m]`), with cycle IDs so late responses cannot decrement a newer recovery cycle; preserves each family's OAuth account identity and newest account-bound Opus 4.8 tail fingerprint for source-model prewarming and later cache bridges. Source-model prewarms remove the server-fallback request field and beta so they always reach the intended source model.

**PromptContextResolver:**
- Purpose: Resolves the active agent, model, variant, and latest message IDs (assistant and user) from the OpenCode session message history
- Location: `packages/opencode/src/prompt-context.ts`
- Pattern: Traverses recent session messages via the client API to reconstruct the current model/variant context for synthetic/ignored notification turns. This prevents OpenCode from resetting to default model configurations or misattributing background prompt notices.

**BillingLineageTracker:**
- Purpose: Correlates user message prompt UUIDs and upstream Anthropic request IDs across tool turns to populate Claude Code billing header request lineage
- Location: `packages/opencode/src/billing-lineage.ts`
- Pattern: Maps user message turns to UUID `promptId`s, carries correlation tokens via `x-cortexkit-billing-lineage` internal request headers, resolves lineage during request transform, commits successful Anthropic request IDs (`req_*`) as `previousRequestId` for subsequent turns in the session, invalidates chains on session clear with generational guards, excludes background messages (compaction, synthetic, lane start) and background agents (`title`, `summary`, `compaction`), and ensures reusable bodies (CacheKeep and source cache warms) strip request-scoped lineage.

**AccountStorage (sidecar file):**
- Purpose: Persisted configuration and runtime state — fallback accounts, quotas, refresh backoff, killswitch settings, cache/relay config
- Location: `packages/core/src/accounts.ts`
- Pattern: JSON file on disk (`~/.config/opencode/anthropic-auth.json` for OpenCode, `~/.pi/agent/anthropic-auth.json` for Pi). Runtime credentials/quota state lives in `anthropic-auth-state.json`; sticky routing affinity lives in `anthropic-auth-routing-state.json`. Atomic writes via temp + rename. Serializes all account-store and state writes via an in-process save mutex and acquires a cross-process write lock on the configuration file during save. Merges existing accounts on disk with incoming accounts on save to prevent fallback account loss under concurrent execution. Refresh file lock acquisition tolerates `ENOENT` and `EINVAL` lost-parent races when creating eviction marker files under high contention. Main and fallback refresh errors are bound to a SHA-256 refresh-token fingerprint: rotating the refresh token clears a permanent old-token `invalid_grant`, while active same-token transient/shared backoffs remain. The main-account clear carries an observation-time fence so stale cross-process writers cannot restore the old latch, and `/claude-account reset-backoff` explicitly clears main refresh plus identity-compatible quota backoffs. A persisted main-account slot ID keeps Claude Code device identity stable across token rotation, while Anthropic's bootstrapped account UUID binds quota/profile state and detects a real account replacement. Quota error clears carry both a generation and observation-time fence so stale cross-process writers cannot resurrect an old restriction. Main-quota cache and persistence ordering derive exclusively from `OAuthQuotaSnapshot.checkedAt`, which is bound to the snapshot's account identity; the legacy standalone `mainQuotaCheckedAt` remains readable but has no ordering authority. Preserves empty scoped quota arrays `[]` on load/merge to distinguish explicit zero-carve-out from missing quota metadata. Malformed sidecar JSON errors expose only the file path, line, column, and generic parse reason; parser source context is redacted before logging so credentials cannot be repeated in diagnostics. Public config persists `thinkingBinding.prefixMismatchBehavior` (`account-default`, `error`, or `drop_block`), defaulting safely to account behavior when absent or invalid.

**rewriteRequestBody:**
- Purpose: Full Anthropic request body transform — handle cache strategies (including legacy model-specific standby bridges), system sanitization, trailing whitespace tool prefill stripping, tool name prefixing, Claude Code 2.1.280 billing headers with session suffix pinning and request lineage, configurable Fable 5.1/Opus 5.5/Sonnet 5.5 adaptive-thinking prefix behavior, mid-conversation effort markers, server-side fallback opt-in/marker restoration, and final-body signing
- Location: `packages/opencode/src/transform.ts`
- Pattern: Idempotent transforms preserve the existing unchanged-body fallback for parse failures. Structural history and effort-correlation errors refuse locally before cache shaping, billing suffix pinning, signing, dumping, or model transport. The Pi provider adapter calls shared Core's `request-history.ts` before converting host messages and again on the outgoing Anthropic history. OpenCode's fetch adapter uses the same outgoing-history guard. Local structural 400 responses carry private in-process identity so custom upstream fallback status policies cannot cause account migration, while genuine provider 400 responses retain their configured policy.

**SidebarState:**
- Purpose: Shared state file between OpenCode server process and TUI widget process for live quota/routing/cache display and per-session safety fallback status
- Location: `packages/opencode/src/sidebar-state.ts`
- Pattern: JSON file under `$TMPDIR`; server writes after each routing decision or quota refresh; TUI polls on interval. Supports displaying standard usage windows alongside scoped model quotas (e.g. Fable weekly limit), omitting standard five-hour and seven-day placeholders when only model-scoped limits are visible, preserving empty scoped arrays `[]` to distinguish explicit ownership from missing data, and carries a bounded set of session-keyed server-side fallback or legacy Opus/Fable recovery notices so concurrent sessions do not overwrite each other's sidebar state. Non-authoritative updates re-read the file before merging to preserve active routing sessions (`activeId`). Cross-process writes are guarded by an `mkdir` directory lock with atomic rename-claim eviction of stale locks, jittered retries, and lock-budget exhaustion skips. Writes are fenced with pre- and post-rename ownership checks; if a post-rename lock loss is detected, a single bounded locked repair restores the routing-authoritative fields into the successor's fresh state.

**TuiPreferences:**
- Purpose: Comment-preserving JSONC preferences and live sidebar configuration reloads
- Location: `packages/opencode/src/tui-preferences.ts`
- Pattern: Atomic temp-file replacement for writes; a synchronously captured content baseline prevents immediate post-registration changes from being absorbed. Directory `fs.watch` events are content-checked and backed by an independent recursive polling loop, which remains active for an existing preferences file even if Bun cannot construct the directory watcher (for example, `EBADF`).

**RPC Server/Client:**
- Purpose: Loopback HTTP server for TUI ↔ OpenCode server IPC — modal dialogs and notification delivery
- Location: `packages/opencode/src/rpc/`
- Pattern: One bearer-authenticated HTTP server on `127.0.0.1` per project RPC directory, with a project-local port file and token for TUI discovery. A process-global registry serializes concurrent same-directory replacement, while identity-fenced leases prevent late disposal from stopping or unlinking a successor. Pending command dialogs require a session-scoped drain so one project's TUI cannot consume another project's process-global queue.

## Error Handling

**Strategy:** Parse failures preserve the original request body; invalid trailing-assistant history and uncorrelated effort markers refuse locally before cache/billing/signing/model dispatch; 429 backoff with exponential retry for token refresh; process-wide main-refresh coalescing across OpenCode project plugin instances; stale-token 401 retries adopt a concurrently persisted replacement credential; retryable stream errors detected and bubbled as synthetic `ECONNRESET` for retry by the caller. Sticky-balanced routing fails retryably while its quota pool is incomplete instead of silently selecting a non-sticky account; once the pool is complete but has no eligible route, it returns an explicit 429 quota block, or a 401 re-login error when the main refresh token is permanently invalid and no fallback can serve the requested model, rather than falling through to the excluded main account. Confirmed five-hour exhaustion with at most 15 minutes until reset returns a deterministic jittered `Retry-After` while retaining affinity. Killswitch blocks requests before they hit the API when quota drops below configured thresholds (including per-model scoped thresholds evaluated against the requested model). Blocks are classified as scoped-driven (when a specific model's weekly limit is reached) or account-level (5h/7d limits), generating detailed user-facing error messages. Fallback routing triggers on confirmed standard quota exhaustion or model-scoped quota exhaustion (stale cached quota never triggers API-key fallback routes). Content-filter handling tries Anthropic's server-side safety fallback first for eligible OAuth Fable 5/5.1 and Opus 5 requests, then activates deterministic client recovery if the response still refuses. Fable 5.1 signed-thinking prefix mismatches caused by host compaction are handled explicitly with Anthropic's `drop_block` control rather than retried as opaque 400 errors. A refusal after a completed tool call preserves that call and continues with its existing result rather than replaying the original turn. Malformed or unrecognized fallback metadata passes through without fabricated state; `legacy` mode bypasses the server policy and uses deterministic client recovery exclusively. Claustrum transport failures back off per handle and fall through to available sidecar credentials; provider-bound custody tombstones fail locally before network refresh, while closing a reconnecting client rejects rather than installing a late replacement.

## Cross-Cutting Concerns

**Test isolation:** OpenCode loads `preload-sandbox.ts` before `setup.ts` so Core's module-level logger/dump defaults capture an isolated TMPDIR before any application imports. The preload confines account, sidebar, CacheKeep, quota-feed, RPC, dump, and Claustrum connection paths to one disposable sandbox. Its HOME/XDG/TMPDIR and config defaults remain sandboxed even when an individual test removes a feature-specific override; setup detection resolves the injected environment, not the developer's process environment. A regression physically writes a sidebar frame after removing the override and verifies the sandbox destination. Process E2E spawns separate children with isolated HOME and XDG paths.

**Logging:** Simple structured logger (`packages/core/src/logger.ts`) writing to `$TMPDIR/opencode-anthropic-auth.log`; relay diagnostics and performance tracing behind `OPENCODE_ANTHROPIC_AUTH_PERF=1` env flag; cache diagnostics records (`MC-CACHE-DIAG `) and deduplicated beta mappings (`MC-CACHE-DIAG-BETAS`) emitted at debug level

**Caching:** In-memory quota cache (`QuotaManager`) with staleness-based refresh logic; memoized system prompt sanitization (`sanitize-memo.ts`) with 8MB max; 1-hour Anthropic prompt cache managed via cache strategy (`cache1h.ts`, `cachekeep.ts`)

**Storage:** Sidecar JSON files for config + credential/quota state (separate files to avoid config overwrite), optional Claustrum scoped roster metadata and owner-only enrollment tokens outside public config, a cross-process locked `anthropic-auth-routing-state.json` containing hashed sticky session assignments, optional owner-only quota observation leases under `$TMPDIR/opencode-anthropic-auth/quota-header-feed/`, a prime marker directory at `$TMPDIR/opencode-anthropic-auth/prime/<storage-fingerprint>/<account-fingerprint>/`, where `anthropic-auth.json` stores the prime opt-in flag and `anthropic-auth-state.json` stores per-account prime usage counters and lineage bindings, comment-preserving JSONC preferences for the TUI (`tui-preferences.jsonc`), JSON state for TUI sidebar IPC at `$TMPDIR/opencode-anthropic-auth/`, and an auto-sweeping dump directory for request payloads and response metadata artifacts capped at 512MB by default (`OPENCODE_ANTHROPIC_AUTH_DUMP_MAX_BYTES` overrides the cap; `0` disables sweeping). The sweeper treats each request's body, metadata, response artifact, and transport capture as one eviction group and cleans stale partial writes independently so size enforcement cannot leave orphaned dump components. When a process has no in-memory request diff baseline, dump capture reads the newest matching same-session body artifact from disk before writing the first post-restart diff.

**Security:** Local OAuth tokens are stored in the sidecar state file (separate from config); Claustrum enrollment tokens live only in owner-only host enrollment files and scoped access tokens never persist to the sidecar, logs, dumps, sidebar state, RPC projections, or command UI; inherited supervised-spawn identities are cleared on Claustrum IPC; sticky routing stores only SHA-256 session hashes, account IDs, quota timestamps, and initial input byte counts; the optional quota feed projects a fixed allowlist and excludes tokens, token hashes, raw headers, request bodies, models, and errors; proxy custom-header configuration is restricted to API-key/non-OAuth routes and cannot replace authentication, Anthropic protocol, body-framing, or internal-correlation headers, while malformed values produce only redacted diagnostics; relay uses a shared secret token; RPC server uses a bearer token; token refresh and configuration/routing writes use file locks to prevent races and concurrent write loss; no secrets are stored in git
