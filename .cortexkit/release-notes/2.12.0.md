## One settings file for OpenCode and Pi

OpenCode 1, OpenCode 2 and Pi now share one settings file, `anthropic-auth.jsonc`, that you can edit by hand. Settings are user-only: no project settings file is read. Host overrides let OpenCode and Pi keep different values, and some cache, fast-mode and thinking settings also take per-model overrides. [The settings file guide](https://github.com/cortexkit/anthropic-auth/blob/main/docs/settings-file.md) has the full path rules, setting names, schema and examples.

**Where it lives**
- Linux and macOS: `$HOME/.config/cortexkit/anthropic-auth.jsonc`
- Windows: `%APPDATA%\cortexkit\anthropic-auth.jsonc`
- With an absolute `XDG_CONFIG_HOME` (any OS): `$XDG_CONFIG_HOME/cortexkit/anthropic-auth.jsonc`
- An absolute `ANTHROPIC_AUTH_SETTINGS_FILE` chooses another file. `/claude` Status shows the file in use.

**What happens when you update**
- Your existing settings move into the new file once, automatically. The move waits until every running OpenCode and Pi copy using them has been updated and restarted.
- With a custom `XDG_CONFIG_HOME` or an explicit settings file path, each host moves only its own settings.
- Moving never weakens protection. Each host keeps at least its own effective killswitch, quota floors, unknown-quota policy and same-account wait, including their defaults. The same rule covers a host picking up the file while running, setup, and recreating a deleted file. If a host's protection can't be read, it keeps its old settings, or the change is refused, until it can.
- A value set on only one host becomes a shared value for both, unless that would weaken the other host's protection.
- The old settings files are not deleted or rewritten.

**Rollback**
You can roll back to 2.11.4. It reads your settings from before the move, so changes made after the move don't carry back.

**Status display**
With the shared file in use, OpenCode 2 and Pi `/claude` Status show the killswitch's default floors (5-hour 5, weekly 10, scoped 0) instead of an empty value. The killswitch stays off, and nothing else changes.

## Fixes

- **Linux storage paths.** While another process was saving, a storage file's path could resolve under the wrong name, which could point a lock or storage id at the wrong file. Paths now resolve safely during saves.
- **Cache after an effort change.** Changing effort mid-session no longer drops the cache marker on the next full request after message-thread continuations, so the prompt cache is reused instead of rewritten.
- **Vault enrollment safety check.** The check that refuses an unsafe enrollment token folder now also holds during token replacement and when a folder check itself fails.
- Updated the shared authentication library to common-auth 0.49.2.
