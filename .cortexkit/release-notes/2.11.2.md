## Fixes

- **Less cache rewriting after a message thread ends.** With message threads, a long session sends a full request again after a pause of five minutes or more, or after its history changes. In some long sessions, Anthropic did not match the cache written during the thread, and the full request rewrote 150k to 344k tokens. The full request now also places a cache marker exactly where the previous full request ended, if everything before it is unchanged and that cache entry is still alive, so it can read that older entry instead. This applies on OpenCode 1, OpenCode 2 and Pi.
- **Threads keep going after a moved cache marker.** On long tool steps and during an Opus recovery round, a full request moves one cache marker. The request after it then put the marker back and restarted the thread with another full request. Continuations now keep the system prompt and tools exactly as the full request sent them, so the thread continues.

Requests outside message threads send the same bytes as before.
