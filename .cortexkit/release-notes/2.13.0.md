## Your own gateway for Claude sign-in requests

You can now send Claude subscription (sign-in) model requests through your own gateway. Set `gateway_url`, and optionally `gateway_headers`, in your user settings file. Sign-in, token refresh and usage checks still go only to Anthropic. [Custom gateway](https://github.com/cortexkit/anthropic-auth/blob/main/docs/settings-file.md#custom-gateway) has the details. Addresses #692.

The gateway is read only from the settings file in its default place for your operating-system account:
- Linux and macOS: `~/.config/cortexkit/anthropic-auth.jsonc`
- Windows: `%APPDATA%\cortexkit\anthropic-auth.jsonc`

The plugin finds that place from your account, not from environment variables. A gateway named in a settings file chosen with `ANTHROPIC_AUTH_SETTINGS_FILE` or `XDG_CONFIG_HOME` is ignored, and `/claude` Status says why. A plain `http:` gateway is refused while `HTTP_PROXY` or `http_proxy` would carry it, unless `NO_PROXY` and `no_proxy` exempt its host.

## Security hardening for relays and sign-in requests

- **Relay location.** A relay is now used only when the account settings are in their default place for your operating-system account. A relay named by account settings moved with an environment variable (`OPENCODE_CONFIG_DIR`, `OPENCODE_ANTHROPIC_AUTH_FILE`, `XDG_CONFIG_HOME`, `PI_ANTHROPIC_AUTH_FILE`, `PI_CODING_AGENT_DIR`) is ignored. Requests then go directly to Anthropic, `/claude` Status says why, and `relay setup` refuses. If you keep your account settings somewhere else on purpose and use a relay, move them back to the default place. [Where the relay is read from](https://github.com/cortexkit/anthropic-auth/blob/main/docs/transports.md#where-the-relay-is-read-from) explains the rule.
- **Plain-text relays and proxies.** A plain `http://` or `ws://` relay is no longer used while `HTTP_PROXY` or `http_proxy` is set, unless `NO_PROXY` and `no_proxy` exempt its host. This means a proxy never sees your sign-in in plain text. `https://` and `wss://` relays are unaffected.
- **TLS checks.** `ANTHROPIC_INSECURE` no longer turns off certificate checks on Claude sign-in requests. It still applies to API-key requests that use `ANTHROPIC_BASE_URL`.
- **Redirects.** Requests to an HTTP relay, and the relay's own requests to Anthropic, no longer follow redirects. A relay Worker you deployed earlier gets this after you redeploy it.

## Fixes

- A `ws://` relay is now reached over `ws://` instead of `wss://`.
- A changed relay URL or secret now applies to the next WebSocket relay request of a conversation already in progress.
- OpenCode 2's `/claude` settings status shows the settings file path again, instead of `[object Promise]`.
- Under Thalamus, OpenCode 2 now reports which login answered after it recovers a rejected conversation thread. Keep-warm and Prime requests refresh quota without counting as answered turns.
