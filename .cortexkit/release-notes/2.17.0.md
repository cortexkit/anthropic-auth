## Changes you may notice

- **OpenCode 2 now uses the five-minute Claude prompt cache by default**, like OpenCode 1 and Pi. An explicit cache setting or an Agent Runner session policy still takes precedence.
- **Paid API-key requests are sent unshaped on every host.** OpenCode 1 and Pi now send them like OpenCode 2: no Claude Code prompt, no billing signature, no renamed tools. Claude subscription requests are unchanged.
- **`ANTHROPIC_INSECURE` is gone.** API-key requests to custom HTTPS addresses always verify TLS, on every host.
- **OpenCode 1 no longer publishes the optional quota header feed.** Quota readings still reach the vault. The `quota_header_feed_enabled` setting is gone and can be removed from your settings file.
- **Pi replies may be as long as the model allows** (128,000 tokens on Opus 5.5 and Fable 5.2), as on OpenCode, instead of 16,384, still fitted to the context window.

## The same behaviour on OpenCode 1, OpenCode 2 and Pi

- OpenCode 2 keeps custom proxy headers off Claude sign-in requests, and shows zero token prices for Claude subscription models by default, like OpenCode 1.
- OpenCode 1 and 2: opt-in Prime can start a quota window without a first chat request, and turning Prime on in the settings file takes effect without a restart.
- Pi links subscription requests to the same user turn across tool calls and retries, reuses an earlier cache boundary after long replies or tool exchanges, updates quota from Claude's replies, and honours the same paid-route model aliases as OpenCode.
- Pi's `/claude` menu can refresh quota, edit quota floors and killswitch thresholds, and start a five-hour quota window.
- OpenCode 1 keeps warming idle sessions across a server restart, reuses the previous full request's cache boundary after a restart, and gzips keep-warm requests, like OpenCode 2. Pi gzips keep-warm requests too.
- On Thalamus, OpenCode 1 asks shared routing in every routing mode, reports waits and per-send usage, and never falls back to a paid API key where routing gave advice, like OpenCode 2.
- OpenCode tools added or removed mid-session keep the same names in Claude requests.

## Keep-warm

- Servers and hosts sharing an account store no longer warm the same saved session twice or overwrite its warm budget. All three hosts use one session claim, and keep-warm requests are sent only by the process that owns the session.
- When OpenCode 2 reloads the plugin without a restart, folders still on the old version keep warming their sessions, and reloaded folders pick up each saved session once the old version stops warming it.
- Saved sessions survive brief storage or Windows file-check errors, a failed request during restart recovery, and the system clock being set back. A newer saved session is never overwritten or deleted by an older one, and a cancelled warm no longer counts against a session's limit.
- OpenCode 1 and 2 no longer wait for saved keep-warm sessions before starting or sending the first request, and OpenCode 2 and Pi no longer wait for optional cache diagnostics before delivering replies.

## Routing and quota

- When shared routing reports that every account is at its concurrent-request limit, requests wait for a free slot instead of ending. OpenCode 2 waits at most four minutes, and cancels its pending routing request when OpenCode abandons the message.
- When Claude can't confirm which account a freshly refreshed login belongs to, the plugin checks again after 5 minutes, then 15, then hourly, instead of blocking the login for up to a day. The message says when it will check again, and **Reset account backoff** in `/claude` checks on the next turn (#880).
- An invalid sticky-routing state file is set aside as a private backup and replaced, with one warning (#876).
- After a revoked vault enrollment is replaced, the plugin uses the new enrollment without a restart (#877).
- OpenCode 2: after a rate limit with no reset time, a newer quota check showing room lets the session send again (#878).

## Setup

- Windows: when the plugin refuses to create its state folder because another account can change a folder above it, the message names that folder and the account, and says how to fix it (#881).
- The one-time state move no longer treats a running older plugin as gone after the system clock is corrected forward.

## Pi and Agent Runner

- Pi places Agent Runner's mid-run instruction changes right after the message they belong to, so the prompt cache holds, and honours Agent Runner's per-run reply length cap.
