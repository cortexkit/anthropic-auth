## New

- **Message threads.** Claude requests now use Anthropic's message threads, as Claude Code does. After the first request in a conversation, each request sends only the new messages, keeping the same system prompt and tools. So requests are much smaller (often tens of kB instead of 1 to 2 MB) and start faster. Anything that changes the earlier conversation, a reply, the model, settings, system prompt or tools sends a full request again. If Anthropic rejects a thread request, the plugin resends it in full before any reply is generated; if it rejects threads for an account, threads turn off for that account until restart. Applies to Claude logins on OpenCode 1, OpenCode 2 and Pi. API-key routes, keep-warm and the WebSocket relay are unchanged.

## Changes

- **Retry twice, then move.** In sticky-balanced routing, after a rate limit Anthropic doesn't confirm as a used-up limit, a session now retries its own account at most twice per turn (up to a minute each), then moves to another account. OpenCode 2 used to move at once, and OpenCode 1 retried until OpenCode gave up.

## Fixes

- **OpenCode 2 plugin reload.** A plugin reload no longer fails the next step of a Claude turn that was already running with "Native custody refused: closed"; the reloaded plugin serves it. (#605)
- **HTTP relay after edits.** Relay requests no longer fail after an edit to an earlier message or an effort change produced overlapping upload patches.

## Dependencies

- `@cortexkit/common-auth` 0.34.0 (Windows lock-release retry, quota sidebar fixes).

To upgrade, quit OpenCode and Pi and run `npx @cortexkit/opencode-anthropic-auth setup`, or change the version in your OpenCode config.
