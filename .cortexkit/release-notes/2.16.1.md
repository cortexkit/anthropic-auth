## Fixes

- **Windows: reading the account file while the plugin updates it no longer fails the request.** On Windows, a read of the account file that overlapped the plugin's own update of that file could end the turn ("Failed to drain Session") or fail the sidebar. The read now waits up to about a second for the update to finish. If the file is still busy after that, OpenCode 1 and Pi retry the request, and on OpenCode 2 a retry stays with OpenCode. One limit remains on OpenCode 2: a turn's first request can still stop if the file stays busy longer than that, because OpenCode 2 has no way for a plugin to retry before the first send. ([#829](https://github.com/cortexkit/anthropic-auth/issues/829))
- **The OpenCode sidebar keeps showing its last account state** while the account file is being updated, instead of failing.
- **common-auth 0.54.1.**
