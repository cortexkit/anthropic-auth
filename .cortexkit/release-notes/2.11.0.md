## Changes under Thalamus

- **Routing refusals stop the request.** When Thalamus's shared routing refuses an account for a request, the plugin now sends nothing and fails the request with a fixed message, instead of quietly picking another account. This applies on OpenCode 2 and Pi. If routing can't be reached or answers too slowly, the plugin keeps its own account choice, as before.
- **Routing's account choice is trusted.** An account that routing chose is no longer refused because of the plugin's own minimum remaining-quota settings, since routing keeps the same reserve. Sign-in state and disabled accounts still apply.
- **Pi asks routing for its account.** Pi now asks shared routing for an account at the start of each turn, keeps that choice when it retries the request, and honours routing's holds and refusals. Its limit reports now reach routing.

Outside Thalamus, request behavior does not change.

## Fixes

- A refresh-lock release interrupted by another process now finishes cleaning up its lock, instead of leaving it to block the next request for up to its timeout (common-auth 0.46.0).

## Dependencies

- common-auth 0.47.0.
