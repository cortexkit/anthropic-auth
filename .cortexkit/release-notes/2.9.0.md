## Account state leaves the OpenCode config folder

**Before you install: update anthropic-auth in every OpenCode and Pi on the machine, then restart all of them, including any Thalamus-hosted server.**

- **What moves:** OpenCode's machine-written account, vault, usage and session state moves out of OpenCode's config folder, which OpenCode 2 watches for changes. It goes into your state folder: `~/.local/state/cortexkit/anthropic-auth/opencode/` (`%USERPROFILE%\.local\state\cortexkit\anthropic-auth\opencode\` on Windows), or under `XDG_STATE_HOME` when set. A custom config folder (`OPENCODE_CONFIG_DIR`) gets its own `opencode-<hash>/` folder.
- **When it moves:** only once no older plugin process is still using the old files. Until then, everything keeps working from the old place. Updating and restarting every host lets the move happen.
- **What stays:** your settings stay in the config folder (`anthropic-auth-pool.json`, `anthropic-auth-vault-settings.json`, `tui-preferences.jsonc`), along with the legacy sign-in files and local routing. Pi's files don't move.
- **Downgrading:** before installing an older version, quit every OpenCode and Pi and run `npx @cortexkit/opencode-anthropic-auth setup --restore-legacy` to put the files back.

## Fixes

- **`/claude` menu after a plugin reload:** the OpenCode TUI's `/claude` menu no longer briefly gets an "unauthorized" error or a dropped connection from the previous plugin instance.
