## Changes

- **Waiting on a used-up account now depends on the session's cache.** In sticky-balanced routing, a session waits on its own used-up account only when that account resets before the session's prompt cache would expire anyway: 1 hour with 1-hour caching, otherwise 5 minutes. Otherwise it moves to an account with room at once. A session that hasn't used its cache on that account waits for nothing. This replaces the fixed 15-minute window.
- **New setting: Longest wait on the same account.** In `/claude` → Routing you can choose **Don't wait** (move at once), **15 minutes** (the default), or **Until the cache expires**. On OpenCode 2 a single wait is at most 15 minutes; with **Until the cache expires** it can wait again on later retries.
- **Pi waits in the plugin.** When an account resets within that limit, Pi now waits and shows the reset time in its working message. Escape cancels at once. Pi only waits for a known reset time.

## Fixes

- **No more multi-day waits when every account is out.** When no account can serve a request, the retry time now comes only from fresh readings of the current accounts, and it follows **Longest wait on the same account**. Before, an old stored weekly reset could make OpenCode 1 wait for days. The message still states when an account can actually serve again. With **Don't wait**, OpenCode and Pi stop instead of retrying automatically.

## Pi fixes (thanks @mhismail3)

- **Effort levels for Opus 5.5.** Pi now offers Opus 5.5's own effort levels, `low` through `max`, instead of `off` and `minimal`, which the model can't honour. (#599)
- **Tool names in replies.** A tool name in Claude's reply is now mapped back only to a tool the request actually sent. A differently cased or unadvertised name no longer runs a different tool. (#597)
- **Request hooks.** Pi's own request hook now runs before the request is signed, as Pi's provider contract requires, and a replacement keeps streaming on. A user message with several text parts is now sent as separate blocks, as Pi's own Anthropic adapter does. Pi sessions that have such messages rebuild their prompt cache once after the upgrade. (#598)
- **1-hour cache on request.** Pi's `cacheRetention: 'long'` now uses Anthropic's 1-hour cache even when 1-hour caching isn't on for every request, and the new wait rule counts that session's cache as lasting 1 hour. (#600)

To upgrade, quit OpenCode and Pi and run `npx @cortexkit/opencode-anthropic-auth setup`, or change the version in your OpenCode config.
