## Fixes

- **After a rate limit, the retry stays on the account that already holds the conversation's cache when it can** (OpenCode 1, OpenCode 2 and Pi). Before, the plugin's own retry choice could pick an account with a cold cache, which then wrote the whole conversation again. On one long OpenCode 2 session that cost about 400,000 to 550,000 written tokens several times in an hour.
- **Shared routing now learns when an account's Fable-only weekly limit is used up.** When Claude refuses a Fable request with a rate limit and the account's last usage reading shows its Fable window full, the plugin tells shared routing, so routing stops sending Fable requests to that account until the limit resets. Before, routing kept choosing the account and every request was refused and retried.
- **OpenCode 2 billing reports keep the HTTP status and Claude request ID of a failed attempt.**
- **Rate-limit refusals that matter to shared routing are logged** with Claude's rate-limit headers (numbers, statuses and reset times only), so a limit that isn't recognised can be diagnosed.
