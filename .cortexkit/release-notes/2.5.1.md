## Fixes

- **Keep-warm retries before the cache expires.** A keep-warm request is sent 5 minutes before a session's cache expires. If it failed briefly (a dropped connection, a timeout), it was retried after 1 minute and then 2, so it got at most two tries before the cache expired. The session's next turn then wrote its whole prompt cache again. Retries now come after about 20, 40 and 60 seconds, so several fit before expiry, and none starts once it can no longer finish in time. A refusal for a real reason, such as a killswitch floor, still stops keep-warm at once. (#610)
- **Keep-warm failures say what failed.** The warning now names the step (authorization, send or response) and the kind of failure, such as a timeout, a connection error code, a vault refusal code or an HTTP status. It never includes error text, credentials or prompt content. On OpenCode 2 the cause was previously replaced by a fixed message. (#610)

To upgrade, quit OpenCode and Pi and run `npx @cortexkit/opencode-anthropic-auth setup`, or change the version in your OpenCode config.
